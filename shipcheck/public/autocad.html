AutoCAD drawings in Complee

A general-arrangement drawing is opened as DXF, checked against the rule set, and the results are written back as a DXF markup in the drawing's own coordinates. Nothing is uploaded: the file is read in your browser.

1. In three steps

  1. In AutoCAD: SAVEAS → AutoCAD DXF (any version from R12 to current, ASCII). DWG is a closed binary format and is not read.
  2. In Complee: Open… and choose the .dxf file. The right panel lists what was read and what was not.
  3. AutoCAD markup downloads the results as DXF. In AutoCAD: XATTACH the file at insertion point 0,0,0, scale 1. Each checked element has a frame on a layer COMPLEE_<DECK>_NON_COMPLIANT (red), …_NOT_ENOUGH_INFO (orange) or …_COMPLIANT (green), with the rule, the measured and the required value as text.

Try it with the sample drawing (two decks, three planted findings, fictional values).

2. Layer convention

The layer name says what an entity is: <DECK>-<TYPE>, for example MD-CORRIDOR or 01-DOOR. The type is the last part of the name; -, _, | and $ separate the parts, upper or lower case. A layer with only a type (STAIRS) belongs to a single deck called DECK.

3. Elements and their values

  • One element is a closed polyline or a block reference on a type layer. Its footprint is the bounding box of the entity; a shape that is not a rectangle gets a note saying so. Open lines and arcs are not elements.
  • Name: text or multiline text placed inside the footprint, on the same layer.
  • Values: block attributes, or lines KEY=VALUE in that text: CLEAR_WIDTH=850mm, SILL_HEIGHT=300mm, HEIGHT=37.4in, WEATHERTIGHT=YES, ZONE=open_deck. Units: mm, cm, m, in, ft; a number without unit is in drawing units. ID= sets the element id (otherwise deck, type and the entity handle), TYPE= overrides the layer's type.
  • Measured widths: a corridor, stair, ramp or ladder without CLEAR_WIDTH gets the drawn width, a door the drawn door width. The value is labelled "measured from the drawing geometry, not a stated clear width". A written value always wins.
  • Missing values stay missing. A sill height or rail height that is not written is reported as not enough info, never assumed.
  • Height in 3D: the entity's Thickness property, or EXTRUSION=2700. A stair without it is assumed to reach the next deck (noted on the element).
  • Traceability: every value shows the file, the layer and the entity handle it came from.

4. Decks and ship particulars

  • Layer <DECK>-OUTLINE: the closed deck outline, text with NAME=, ELEVATION= and HEIGHT= (the outline's own elevation is used when ELEVATION is not written), and optionally one POINT.
  • Decks drawn side by side on one sheet: put a POINT on each deck's outline layer at the same reference position of the ship (for example aft perpendicular on the centreline). Complee stacks the decks on these points, and the markup is written back at them.
  • Stairs connect two decks only when the decks have elevations.
  • Layer COMPLEE-SHIP: text with the ship particulars the rules depend on, one per line: NAME=, TYPE=research (or passenger, cargo, special_purpose), LENGTH_OVERALL=60.6m, BEAM=, GROSS_TONNAGE=, CLASS_SOCIETY=DNV, OPERATING_AREA=US, Caribbean, BERTHS=. Without them, rules that depend on the ship report not enough info.
  • Drawing unit: the UNITS setting of the drawing (millimetres, centimetres, metres, inches, feet). A drawing without a unit is read as millimetres (inches for an imperial drawing) and flagged.

5. Limits

  • 2D plan geometry only: 3D solids, hatches, dimensions, ellipses and splines are not read (they are counted in the import summary).
  • Footprints are axis-aligned boxes; a rotated block is covered by its bounding box.
  • Results are an aid for the engineer's review. Rule values are unverified until checked against the official text.
